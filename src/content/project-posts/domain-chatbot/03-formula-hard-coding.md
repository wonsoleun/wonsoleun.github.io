## 1. 수식 하드 코딩

PDF 자동 변환으로 얻은 수식이 틀린 경우가 많았다. 수식은 규정 답변의 핵심이라 틀리면 답변 전체를 믿을 수 없다.
→ 자동으로 고치기보다, **틀릴 만한 수식을 자동으로 골라내고 사람이 확인하는** 방식을 택했다.

| 순서 | 할 일 | |
|---|---|---|
|[1]| 의심 수식 골라내기 | 관계 기호 없음, 본체가 짧음, 괄호 짝 안 맞음, 반복 → 의심 표시 |
|[2]| 검수 목록 만들기 | 수식마다: PDF 쪽, 위치, 자동 LaTeX, 원본 이미지 |
|[3]| 눈으로 확인 | 원본 이미지와 KaTeX로 그린 결과를 나란히 보는 검수용 HTML에서 맞음/틀림 표시 |
|[4]| 틀린 것만 기록 | 수정 목록 파일에 "틀린 LaTeX → 맞는 LaTeX" |
|[5]| 파싱 다시 실행 | parse 단계에서 수정 목록을 적용 (PDF 재변환 없음) |
|[6]| 인덱스 다시 만들기 | 본문이 바뀌었으니 인덱스 재생성 |

→ 수정 내용을 원본 PDF가 아니라 별도 파일로 관리해서, 파서를 다시 돌려도 수정이 사라지지 않게 했다.


### 과정

Part 2(재료·용접), Part 3(선체), Part 5(선종)의 의심 수식을 검수용 화면에서 직접 하나하나 확인했다............



### 결과

**검수 결과**

의심 표시된 수식의 **대부분이 실제로 틀려** 모두 수정했다. 맞은 것은 일부뿐이었다.
<br> → 단순한 규칙(관계 기호, 길이, 괄호, 반복)만으로도 틀린 수식을 꽤 정확하게 골라낼 수 있었다

| 수정 유형 | 주로 나온 곳 | 내용 |
|---|---|---|
| 빠진 본체 입력 | Part 2 | 번호 `( 1 )`만 인식된 자리에 식 본체를 넣음 |
| 잘못 인식 정정 | Part 3, 5 | 잘리거나 깨진 LaTeX를 원본대로 다시 씀 |
| 수식 아님 제거 | Part 5 | 수식이 아닌데 수식으로 인식된 것을 본문에서 뺌 (가장 많음) |

<br>

**검수한 수식 유형**

1. 빠진 본체 (Part 2)
- Docling이 식 번호 `( 1 )`만 수식으로 인식하고 왼쪽의 본체는 수식으로도, 그림으로도, 글자로도 인식하지 않음
- 파서는 번호만 있는 항목을 버리게 되어 있어서 식이 통째로 사라짐
- e.g. Pt.2 Ch.1 Sec.2 [3.3]: 본문이 `Equation (1):`에서 끝나고 Ceq·Pcm·CET 식이 없었음. Part 2의 다른 조항들이 "식은 Ch.1 Sec.2 [3.3] 참조"라고 하는 바로 그 식들
-> 번호만 인식된 항목을 "본체가 빠진 식"의 표시로 보고, 그 자리에 본체를 넣도록 함

2. 수식 아님 (주로 Part 5)
- 대부분이 IGC Code 참조 문구 `(IGC Code Ch.x x.x)`가 수식으로 인식된 것 (Pt.5 Ch.7 액화가스 운반선)
- Guidance note 끝 표시 `---e-n-d---o-f---`가 깨져서 기존 쓰레기 필터를 빠져나간 것도 있었음
- 나머지는 `f o r`처럼 조건 문장의 일부가 수식으로 잘려 나온 것

-> 검색 순위는 그대로. 검색이 아니라 **답변에 맞는 수식이 들어가게 하는** 작업이구나...

## 2. 참조 조항 따라가기 

### 문제
- 질문: "How is the effective breadth of attached plating calculated?"
- 1위 Pt.5 Ch.3 Sec.2 [5.1]: "... calculated according to **Pt.3 Ch.3 Sec.7 [1.3.2]**" → 식이 없음
- 정답 [1.3.2]는 **2위**, 1·2위 점수 차가 아주 작음
-> 검색이 못 찾은 게 아니라, 질문과 문장이 더 비슷한 **안내 조항**에 1위를 내준 것

규정 문서는 "다른 조항에 따라 계산하라"는 식으로 서로를 많이 참조한다. 순위를 억지로 바꾸기보다, **1위 조항이 가리키는 곳을 따라가서 함께 보여주는** 쪽이 규정을 읽는 사람의 방식과 같다고 판단했다.


### 해결
- 파서가 이미 저장해 둔 조항 참조(`refs`)를 이용해, 1위 조항이 가리키는 조항을 한 단계 따라감
- 조항 참조만, 코퍼스에서 찾은 것만, 최대 몇 개까지만. 검색 순위는 바꾸지 않음
- 따라갈지 말지의 기준값은 평가셋에서 조정
- 웹: 답변 아래 "참조 조항" 블록 / LLaMA: `referenced by [1]`로 함께 입력

```text
top = search(query)[0]
for ref in top.refs:                       # 검색이 일치한 문단의 참조 먼저
    if ref is 조항 참조 and 코퍼스에 있음:
        show(article_of(ref), highlight=ref)
```

## 3. Section 제목 일치에 가점 주기

### 문제
- 지난 로그에서 남은 오답이 Pt.2에 몰려 있었음
- Pt.2 Ch.2는 Section이 제품별(rolled steel, steel forgings, steel castings, clad steel …)이고, 같은 번호 조항의 문장이 거의 같음
- "steel **castings**" 질문에 forgings 조항이 1위로 나옴
-> 본문은 거의 같고, **제품을 구분하는 단서는 Section 제목에만 있다**

### 해결
- 질문 단어와 Section 제목의 일치도(idf 가중, 0~1)를 계산해 가장 잘 맞는 Section 하나에만 가점 주기
- `steel`처럼 모든 제목에 있는 단어는 무게가 거의 0, `castings`·`clad`는 큼 → 제품을 구분하는 단어에만 반응
- 다른 Part에 영향을 주지 않도록 범위는 Pt.2의 제품별 Chapter로 제한하고, 일치도가 충분히 높을 때만 적용
- 가중치와 기준값은 평가셋에서 조정

```text
match = Σ idf(맞은 제목 단어) / Σ idf(제목 단어)
dense  += w1 × match      # 재정렬 후보 선정
rerank += w2 × match      # 최종 순서
```

### 결과

- 가점을 더하니까 Top-1 정확도가 재정렬만 했을 때보다 더 올라감
- 늘어난 정답은 모두 Pt.2에서 나왔고, 다른 Part의 정답 수와 Top-5는 그대로 유지 → 범위를 좁게 잡은 덕분에 다른 Part를 흔들지 않음
